# VDJdb per-epitope clustering

Этот каталог содержит обёртку для запуска TCRemP/TCRemPNet на VDJdb по отдельным эпитопам:
[vdjdb_clusters_launch_with_transform.py](/c:/Users/lizzka239/projects/tcrempnet/vdjdb_redcea/vdjdb_clusters_launch_with_transform.py).

Скрипт:

1. берёт `vdjdb_full.txt`-подобную таблицу;
2. выбирает одну цепь (`TRA` или `TRB`);
3. разбивает данные по `antigen.epitope`;
4. для каждого эпитопа считает или подгружает TCRemP-эмбеддинги;
5. проецирует sample и background в общее PCA-пространство, обученное на фоне;
6. строит joint kNN-граф и запускает Leiden;
7. считает enrichment относительно background;
8. сохраняет таблицы кластеров и HTML-визуализацию.

## Что должно быть на входе

- `--vdjdb`: TSV в формате, совместимом с `vdjdb_full.txt`.
- `--background-airr`: AIRR-таблица фонового репертуара.
- `--background-embedding`: parquet с уже посчитанными эмбеддингами для этого background.

Для `TRA` в VDJdb ожидаются колонки `cdr3.alpha`, `v.alpha`, `j.alpha`, для `TRB`:
`cdr3.beta`, `v.beta`, `j.beta`.

## Базовый запуск

```bash
python vdjdb_redcea/vdjdb_clusters_launch_with_transform.py \
  --vdjdb vdjdb_redcea/vdjdb-2025-12-29/vdjdb_full.txt \
  --background-airr data/background_trb.airr.tsv \
  --background-embedding results/background_trb_embeddings.parquet \
  --output results/vdjdb_trb \
  --chain TRB \
  --species HomoSapiens \
  --nproc 8
```

Если нужно обработать только выбранные эпитопы:

```bash
python vdjdb_redcea/vdjdb_clusters_launch_with_transform.py \
  --vdjdb ... \
  --background-airr ... \
  --background-embedding ... \
  --output results/vdjdb_trb \
  --chain TRB \
  --epitopes GILGFVFTL NLVPMVATV \
  --min-epitope-clonotypes 30
```

## Что лежит в output

Скрипт создаёт три подкаталога:

- `airr_format/`: AIRR-таблицы по отдельным эпитопам.
- `tcremp/`: эмбеддинги sample-эпитопов и обученный `background_transform.joblib`.
- `tcrempnet/`: результаты кластеризации, summary и HTML-графики.

Основные файлы:

- `*_sample_embeddings.parquet`: эмбеддинги конкретного эпитопа.
- `*_tcremp_clusters.tsv`: кластеры для sample + background.
- `*_summary_tcrempnet.tsv`: summary по кластерам с enrichment-статистикой.
- `*_clustered_sample_clonotypes.tsv`: только sample-клонотипы, попавшие в кластеры.
- `*_cluster_members.tsv`: таблица в формате, удобном для downstream-анализа.
- `*_clusters.html`: UMAP sample-клонов на фоне density map background.
- `tra_vdjdb_clustered_clonotypes.tsv` / `trb_vdjdb_clustered_clonotypes.tsv`: объединённый результат по всем эпитопам.

## Осмысленные аргументы

Ниже перечислены именно те параметры, которые реально влияют на биологический или технический смысл запуска.

### Данные и отбор эпитопов

- `--vdjdb`: входная таблица VDJdb.
- `--background-airr`: AIRR-файл фона, относительно которого считается enrichment.
- `--background-embedding`: parquet фоновых эмбеддингов. Его лучше считать один раз и потом переиспользовать.
- `--epitopes`: список эпитопов для точечного прогона.
- `--min-epitope-clonotypes`: минимальный размер эпитопа. Полезно, чтобы отрезать слишком маленькие группы, где кластеризация нестабильна.
- `--chain {TRA,TRB}`: запуск по одной цепи за раз. Для этого скрипта это один из главных параметров.
- `--species`: должен соответствовать аннотации V/J-генов и выбранной библиотеке сегментов.

### Эмбеддинги

- `--prototypes-path`: путь к пользовательскому набору прототипов. Если не указан, используются встроенные.
- `--n-prototypes`: сколько прототипов брать. Больше прототипов обычно даёт более богатое представление, но заметно увеличивает время и размер эмбеддингов.
- `--sample-random-prototypes`: включать только если вы сознательно хотите случайную подвыборку прототипов.
- `--random-seed`: фиксирует подвыборку прототипов и другие случайные шаги.
- `--lower-len-cdr3`, `--higher-len-cdr3`: фильтр по длине CDR3. Имеет смысл менять только если у вас специфический датасет или нестандартная очистка входа.

### Кластеризация

- `--cluster-pc-components`: сколько PCA-компонент оставить перед kNN/Leiden.
- `--k-neighbors`: размер локального графа соседей.
- `--leiden-resolution`: управляет дробностью кластеров.
- `--cluster-min-samples`: в этом скрипте используется как минимальный размер кластера при постобработке Leiden.

### Вычислительные параметры

- `--nproc`: число потоков/процессов для FAISS и эмбеддинга.
- `--n-bg-points`: ограничивает число фоновых клонотипов. Самый полезный технический рычаг, если фон слишком большой и всё работает медленно или упирается в память.
- `--output`: директория результатов.
- `--index-col`: пользовательский идентификатор, если его нужно протащить через выходные таблицы.

## Что обычно имеет смысл двигать

### В первую очередь

- `--min-epitope-clonotypes`
  Отсекает маленькие эпитопы. Практически всегда полезно поставить порог, например `20-50`.

- `--n-bg-points`
  Главный параметр для ускорения. Если background очень большой, начните с `50000-200000` и смотрите на стабильность результатов.

- `--leiden-resolution`
  Главный параметр гранулярности кластеров.
  Меньше значение: более крупные и грубые кластеры.
  Больше значение: более мелкие и дробные кластеры.

- `--k-neighbors`
  Имеет смысл двигать вместе с `--leiden-resolution`.
  Типичный диапазон для проб: `4-15`.

- `--cluster-pc-components`
  Если данных мало, `50` может быть избыточно; если данных много и разнообразие высокое, иногда имеет смысл поднять до `75-100`.

### Иногда имеет смысл

- `--n-prototypes`
  Если нужен быстрый exploratory run, можно уменьшить. Для финального прогона обычно лучше не делать слишком маленькое значение.

- `--epitopes`
  Удобно для дебага и точечных сравнений, прежде чем запускать всё VDJdb.

- `--lower-len-cdr3`, `--higher-len-cdr3`
  Стоит трогать только если вы точно понимаете, какие последовательности хотите дополнительно исключить.

## Что обычно лучше не трогать без причины

- `--metrics`
  По умолчанию используется `dissimilarity`; это ожидаемый режим для текущего пайплайна.

- `--sample-random-prototypes`
  Случайная подвыборка ухудшает воспроизводимость, если она не нужна специально.

- `--sample-random-clonotypes`, `--n-clonotypes`
  Для этого сценария обычно лучше не сэмплировать сами VDJdb-эпитопы, иначе можно потерять редкие, но важные кластеры.

## Практический порядок подбора параметров

1. Сначала зафиксировать `--chain`, `--species`, корректный `background`.
2. Поставить `--min-epitope-clonotypes`, чтобы убрать совсем маленькие эпитопы.
3. На пробном прогоне ограничить фон через `--n-bg-points`.
4. Потом подбирать `--leiden-resolution` и `--k-neighbors`.
5. Только если нужно, уже после этого трогать `--cluster-pc-components` и `--n-prototypes`.

## Замечания по использованию

- Background transform обучается на фоне и автоматически сохраняется в `OUTPUT/tcremp/{chain}_background_transform.joblib`. При повторном запуске он будет переиспользован.
- Если для эпитопа уже есть сохранённый parquet эмбеддингов в `tcremp/`, скрипт их не пересчитывает.
- `--n-bg-points` обрезает фон по первым строкам, а не случайно. Для воспроизводимости это удобно, но важно помнить при интерпретации.
- Булевы параметры в текущем CLI объявлены через `type=bool`, поэтому передавать их лучше явно, например `--sample-random-prototypes True`.

## Когда результаты стоит считать подозрительными

- эпитоп едва проходит минимальный порог по числу клонотипов;
- кластеров слишком много или почти нет после небольшого изменения `--leiden-resolution`;
- результат сильно меняется при умеренном изменении `--n-bg-points`;
- фон плохо сопоставим с VDJdb по цепи, виду или качеству аннотации.
